# 변경 이력

## 1.2.0 (2026-11-23)

v1.1 검토에서 확인한 문제를 고쳤다. v1.1 검사기는 768칸만 채우면 재방문 0건, 신규 발굴 생략, 발견 공고 판정 누락, 근거 없는 모집 중 판정, 출처 상태 충돌, 중복 job_key를 모두 PASS로 통과시켰다.

- 조사 순서: 단계별 전체 순회 → **유형 01→10을 하나씩** 진행. `start-type`/`finish-type`으로 순서를 강제하고, 진행 중인 유형이 아닌 기록은 거부한다.
- 이전 조사표: `init --baseline`으로 xlsx(v1.1 형식, BR-xxx ID·13채널) 또는 v1.2 장부 JSON에서 재방문 대상을 가져온다. 유형 미배정 URL이 있으면 조사 시작을 막는다.
- 신규 발굴: 후보별 법인 검색 64개 + 유형별 기업명 비고정 검색 80개를 계획으로 생성하고, 실행 기록과 대조한다.
- 발견→판정: `discovered`·`decisions`를 추가했다. 목록·검색에서 본 관련 공고 수(`relevant_found`)와 등록 수, 등록 공고와 최종 판정을 1:1로 대조한다.
- 공고: 게시 주체(direct/parent/agency)와 실제 채용 법인, 출처별 상태, 모집 중 원문 근거, 충돌 시 `unknown_conflict`, 필수 항목(근무지·경력·고용형태·마감·적합도·원문)을 검사한다.
- 시각: 도구가 KST 시각을 자동 기록하고, 모든 기록이 해당 유형 작업 구간 안에 있는지 검사한다(이전 회차 날짜 복사 차단).
- 판정: 유형별 complete/partial/not_done과 전체 COMPLETE(0)/PARTIAL(1)/FAIL(2). 접근 제한은 부분 조사, 정상 조사 후 0건은 완료(0건), 기록 누락은 미실시로 구분한다.
- 보고서: `report` 명령이 휴대폰 요약·유형별 상태표·공고 목록·미확인 항목을 생성한다.
- 호스트: Claude와 GPT 공용. 계약 파일 자동 탐색(`/mnt/data` 포함), ChatGPT 맞춤형 GPT용 지침·지식 파일 패키지 추가.
- 파일: `scripts/ledger.py` 신설(`init_coverage.py`·`audit_coverage.py`는 호환용 래퍼). `coverage_gate.md`·`report_schema.md`는 `ledger_schema.md`로 통합.
- 남은 한계: 실제로 페이지를 열었는지, 원문 문구와 기록이 같은지는 검사할 수 없다. `ledger_schema.md` 3절의 표본 대조로 확인한다.
